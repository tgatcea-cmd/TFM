# TFM Server API Integration Guide

This document outlines the API integration protocols for connecting clients (such as the Flutter mobile app) to the self-hostable telemetry sync and file sharing server.

---

## Authentication

All protected API endpoints require Bearer token authentication in the headers:

```http
Authorization: Bearer <API_KEY>
```

---

## 1. Device Telemetry Sync Service

The sync service allows clients to push new telemetry records to the server (Upsert) and pull updates generated by other devices using a standard JSON REST API.

### 1.1 Client Push (App -> Server)
Pushes an array of telemetry records to the server. If a record with the same `deviceIdentifier` and `tsMs` already exists, its values are updated (Upsert).

* **Endpoint**: `POST /api/sync`
* **Content-Type**: `application/json`
* **JSON Body Example**:
  ```json
  {
    "records": [
      {
        "deviceIdentifier": "device_sensor_01",
        "tsMs": 1784127674369,
        "value": 45.2,
        "depthCm": 10
      }
    ]
  }
  ```
* **Response**: `200 OK`

#### Flutter/Dart Implementation:
```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

Future<void> pushTelemetry(List<Map<String, dynamic>> records, String apiKey) async {
  final response = await http.post(
    Uri.parse('http://<server-ip>:3000/api/sync'),
    headers: {
      'Authorization': 'Bearer $apiKey',
      'Content-Type': 'application/json',
    },
    body: jsonEncode({'records': records}),
  );

  if (response.statusCode == 200) {
    print('Telemetry push successful.');
  } else {
    print('Failed to push telemetry: ${response.body}');
  }
}
```

### 1.2 Client Pull (Server -> App)
Fetches new or updated telemetry records for a specific device that occurred after a given timestamp.

* **Endpoint**: `GET /api/sync`
* **Query Parameters**:
  * `deviceIdentifier` (Required): The unique ID of the device to query.
  * `since` (Required): The timestamp (in milliseconds) of the last successful sync.
* **Response**: `200 OK`
  ```json
  {
    "records": [
      {
        "deviceIdentifier": "device_sensor_01",
        "tsMs": 1784127674369,
        "value": 45.2,
        "depthCm": 10,
        "updatedAt": 1784127675000
      }
    ]
  }
  ```

#### Flutter/Dart Implementation:
```dart
import 'dart:convert';
import 'package:http/http.dart' as http;

Future<List<dynamic>> pullTelemetry(String deviceId, int sinceTimestamp, String apiKey) async {
  final response = await http.get(
    Uri.parse('http://<server-ip>:3000/api/sync?deviceIdentifier=$deviceId&since=$sinceTimestamp'),
    headers: {
      'Authorization': 'Bearer $apiKey',
    },
  );

  if (response.statusCode == 200) {
    final data = jsonDecode(response.body);
    return data['records'];
  } else {
    throw Exception('Pull failed: ${response.body}');
  }
}
```

### 1.3 Pico & Device Discovery (Repopulate)
Fetches registered picos / stations from the cloud database to repopulate local database entries.

* **Endpoint**: `GET /api/picos` (Aliases: `GET /api/devices`, `GET /api/stations`)
* **Response**: `200 OK`
  ```json
  {
    "picos": [
      {
        "deviceIdentifier": "pico_01",
        "name": "Pico pico_01",
        "lat": 38.609536,
        "lon": -0.4063232,
        "latitude": 38.609536,
        "longitude": -0.4063232,
        "utcOffset": 60,
        "updatedAt": 1784127675000
      }
    ]
  }
  ```

### 1.4 Prediction & Recommendation Sync Service
Dedicated endpoint for syncing Station LSTM predictions and App Irrigation Recommendations.

#### 1.4.1 Client Push (App / Station -> Server)
* **Endpoint**: `POST /api/predictions`
* **Content-Type**: `application/json`
* **JSON Body Example**:
  ```json
  {
    "records": [
      {
        "deviceIdentifier": "pico_01",
        "tsMs": 1784127674369,
        "value": 32.4,
        "depthCm": 30,
        "kind": "prediction",
        "model": "LSTM",
        "confidence": 0.95
      }
    ]
  }
  ```
* **Response**: `200 OK`

#### 1.4.2 Client Pull (Server -> App)
* **Endpoint**: `GET /api/predictions`
* **Query Parameters**:
  * `deviceIdentifier` (Required): Unique device identifier.
  * `since` (Optional): Timestamp in ms of the last successful sync.
* **Response**: `200 OK`
  ```json
  {
    "records": [
      {
        "deviceIdentifier": "pico_01",
        "tsMs": 1784127674369,
        "value": 32.4,
        "depthCm": 30,
        "kind": "prediction",
        "model": "LSTM",
        "confidence": 0.95,
        "updatedAt": 1784127675000
      }
    ]
  }
  ```

## 2. File Sharing Service

The file sharing service manages files (such as random_forest models, reports, or configuration files) in the shared storage folder.

### 2.1 List Shared Files
* **Endpoint**: `GET /api/files`
* **Response**: `200 OK`
  ```json
  {
    "files": ["model_v1.dart", "model_v1.tflite", "report_june.pdf"]
  }
  ```

### 2.2 Download File
* **Endpoint**: `GET /api/files/download?name=<filename>`
* **Response**: Binary octet-stream of the file contents.

### 2.3 Upload File
* **Endpoint**: `POST /api/files/upload?name=<filename>`
* **Content-Type**: `application/octet-stream`
* **Validation**: Restricts upload file extensions. Allowed extensions: `.dart`, `.tflite`, `.txt`, `.pdf`, `.png`, `.jpg`
* **Response**: `200 OK`
  ```json
  {
    "message": "File uploaded successfully",
    "name": "model_v1.dart"
  }
  ```

### 2.4 Delete File
Requires safety verification: client must send a header with the name of the file to confirm intention.

* **Endpoint**: `POST /api/files/delete?name=<filename>`
* **Headers**:
  * `X-Confirm-Filename`: `<filename>` (must match the query name exactly)
* **Response**: `200 OK`
  ```json
  {
    "message": "File model_v1.dart successfully deleted"
  }
  ```

#### Flutter/Dart Implementation:
```dart
import 'package:http/http.dart' as http;

Future<void> deleteSharedFile(String fileName, String apiKey) async {
  final response = await http.post(
    Uri.parse('http://<server-ip>:3000/api/files/delete?name=$fileName'),
    headers: {
      'Authorization': 'Bearer $apiKey',
      'X-Confirm-Filename': fileName, // Safety verification test
    },
  );

  if (response.statusCode == 200) {
    print('File deleted.');
  } else {
    print('Delete failed: ${response.body}');
  }
}
```

## 3. LoRaWAN & Pico Station Integration

Handles binary uplink decoding from LoRaWAN network servers (ChirpStack / TTN / custom) and manages downlink configuration patch queues for `pico_station`.

### 3.1 LoRaWAN Webhook Uplink
Decodes compact priority payloads automatically and saves data into `HistoricValue`, `StationLocation`, or `StationForecast`.

* **Endpoint**: `POST /api/lora/uplink`
* **Headers**: `Authorization: Bearer <API_KEY>` (or `x-device-eui: <eui>` for direct devices)
* **Body Formats Supported**:
  - Raw binary stream
  - Hex JSON: `{"deviceIdentifier": "pico_01", "payloadHex": "0217036680026e6d80003c"}`
  - ChirpStack Webhook: `{"deviceInfo": {"devEui": "..."}, "data": "Base64..."}`
  - TTN Webhook: `{"end_device_ids": {"dev_eui": "..."}, "uplink_message": {"frm_payload": "Base64..."}}`
* **Response**: `200 OK`
  ```json
  {
    "message": "LoRa uplink processed successfully",
    "decoded": {
      "type": "COORDS",
      "lat": 38.609536,
      "lon": -0.4063232,
      "utcOffset": 60
    },
    "downlink": {
      "id": 1,
      "tlvPatchHex": "0102000A"
    }
  }
  ```

### 3.2 Queue Configuration Downlink (App -> Server)
Allows `user_device` to send incremental configuration TLV patches to be picked up by `pico_station` on its next uplink.

* **Endpoint**: `POST /api/lora/downlink`
* **Content-Type**: `application/json`
* **JSON Body**:
  ```json
  {
    "deviceIdentifier": "pico_01",
    "tlvPatchHex": "0102000A"
  }
  ```

### 3.3 Station Status & Location
Query latest metadata, GPS coordinates, and pending downlinks for a given station.

* **Endpoint**: `GET /api/station/status?deviceIdentifier=<id>`
* **Response**: `200 OK`
  ```json
  {
    "deviceIdentifier": "pico_01",
    "location": {
      "deviceIdentifier": "pico_01",
      "lat": 38.609536,
      "lon": -0.4063232,
      "utcOffset": 60,
      "updatedAt": 1784127675000
    },
    "pendingDownlink": null
  }
  ```
