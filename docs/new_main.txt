USER FIRST TIME INTERACTION:
  
  opens the app.
  grants permissions if needed.
  enables bluetooth, and may enable some sort of internet connection.
  
  If it's the first time opening it the configuration menu opens up automatically.

  If Local database has stored devices then a Local DB button appears.
  If Server connection then a Cloud DB button appears.
  Scan for Devices (using BLE) button appears.

  As local database and server we assume are empty this time, the user only sees "Scan for Devices".
  After pressing, a list of nearby BLE devices with the specific Service UUID filter appear, with a "Connect" button.
  When "Connect" is pressed a connection routine is launched.
  When connected an inference routine is launched.

  It's clearly visible what stage of each routine the system is processing, so the user always knows what the system is doing and that is not halt.

  If all was succesfull charts get drawn using the unified chart.
  The default charts are visible: radiation and humidity, the last one displays the LSTM forecast from the inference routine.

  A "Get Irrigation Prediction for <Next yellow zone date>" button appears if we are in the "Forecasting Available" green zone, lstm was succesfull for the current date, and we have the necessary OpenMeteo data.
  on "Get Irrigation Prediction for <Next yellow zone date>" press, the random_forest.dart model launches as inference.
  On random_forest.dart output we got 2 classes: 0 (Better to Irrigate as scheduled) || 1 (Irrigation Not Recommended, high saturation risk)
  Random forest output recomendation are clearly visible for the user.

  A small "+" button is shown next to the chart section title, when pressed a chart manger menu opens up.
  A refresh button is shown at the appbar, it triggers the inference routine again.
  A configuration button is shown at the appbar, it opens the configuration menu.
  A floating button appears with the name of the connected device if any, when pressed ble starts scanning and shows nearby devices, user can change device, disconnect from current, or cancel search and go back.

import urllib.request
import urllib.parse
import urllib.error
import json
import os

# ponytail: Zero-dependency Python standard library script. No 'requests' pip package needed.
API_KEY = "secret_tfm_token" # Default from docker-compose.yml
BASE_URL = "http://localhost:3000"
HEADERS = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json"
}

def request(method, path, data=None, headers=None):
    url = f"{BASE_URL}{path}"
    req_headers = HEADERS.copy()
    if headers:
        req_headers.update(headers)
    
    body = None
    if data is not None:
        if isinstance(data, dict):
            body = json.dumps(data).encode('utf-8')
        else:
            body = data # Treat as binary
            
    req = urllib.request.Request(url, data=body, headers=req_headers, method=method)
    try:
        with urllib.request.urlopen(req) as response:
            res_body = response.read()
            try:
                return response.status, json.loads(res_body.decode('utf-8'))
            except:
                return response.status, res_body
    except urllib.error.HTTPError as e:
        return e.code, e.read().decode('utf-8')
    except Exception as e:
        return 500, str(e)
