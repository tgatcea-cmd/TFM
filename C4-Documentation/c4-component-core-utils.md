# C4 Model - Level 3: Component Documentation
# Component: Core Utilities & Theme

This document provides C4 Component-level (Level 3) architectural documentation for the Core Utilities and Theme subsystem, synthesizing the `lib/core/theme`, `lib/core/utils`, and `lib/core/utils/l10n` modules.

---

## 1. Overview Section

The **Core Utilities & Theme Component** is a foundational, cross-cutting layer within the TFM Predictive Irrigation System application. It centralizes the application's design system tokens, cross-cutting stateless utility functions (such as temporal formatting), and comprehensive internationalization (i18n) / localization (l10n) services. By encapsulating these responsibilities, it acts as the innermost unified base layer that supports the presentation, domain, and data layers without carrying external dependencies.

## 2. Purpose Section

The primary purpose of this component is to provide shared, immutable infrastructure required by all other application layers, ensuring high cohesion and zero cyclic coupling:
- **Visual Consistency**: Establishes the application's visual language via strict Material 3 design tokens, semantic domain-driven colors, and reusable container decorations.
- **Data Uniformity**: Ensures consistent temporal data parsing, formatting, and bucketing across telemetry displays and local storage structures.
- **Global Communication**: Provides a centralized, strongly-typed bilingual string catalog (English and Spanish) to drive all UI elements, hardware status messages, and agronomic recommendations.

## 3. Software Features Section

The component delivers three main sets of features:

### 3.1 Design System & Theme Engine (`lib/core/theme`)
- **Single Source of Truth**: Eliminates inline color or style declarations across UI screens.
- **Semantic Mapping**: Contextually binds colors to hardware connectivity states, warning levels, and agronomic AI verdicts (e.g., `waterActionAccent` exclusively for "IRRIGATE" recommendations).
- **Spatial Rhythm & Typography**: Enforces a strict 8dp layout grid (`spaceXS` to `spaceXL`) and a dual-typography contract separating UI prose (sans-serif) from telemetry readouts (monospace).

### 3.2 Temporal Utilities (`lib/core/utils`)
- **Universal Date Formatting**: Converts disparate input types (`int` epoch milliseconds, `String` ISO strings, `DateTime` objects) into uniformly formatted outputs (`YYYY-MM-DD HH:mm:ss`).
- **Temporal Bucketing**: Offers functional extensions (`floorToHour()`) for snapping telemetry and time-series data to hourly intervals, critical for aggregating sensor inputs and executing predictions.

### 3.3 Localization Subsystem (`lib/core/utils/l10n`)
- **Strongly Typed Messaging**: Replaces hardcoded UI text with compiled properties and interpolation methods.
- **Bilingual Catalogs**: Supports English (`en`) and Spanish Castilian (`es`) seamlessly through the Flutter localization delegate structure.
- **Domain-Specific Vocabularies**: Covers strings for generic shell UI, BLE nearby scanning, hardware synchronizations, cloud emulations, and Open-Meteo configurations.

## 4. Code Elements Section

The component encapsulates the following critical code structures:

### 4.1 Theme Elements
- **`AppStyles` (Class)**: A static repository exposing layout variables (`spaceMD`), color tokens (`surfaceColor`, `successAccent`), text styles (`consoleBody`, `displayHeader`), and global layout builders (`cardShell`, `aiRecommendationCard`). It also assembles the root `ThemeData` (`darkTheme`).
- **`STYLE.md` (Specification)**: Governance documentation outlining design principles, component restrictions, and mandatory PR compliance checklists.

### 4.2 Utility Elements
- **`AppDateFormatter` (Class)**: A stateless utility containing the `format(dynamic value, {bool showSeconds})` method to parse and standardize time representations safely.
- **`DateTimeFloor` (Extension)**: Syntactic sugar on `DateTime` providing `floorToHour()` for time truncation.

### 4.3 Localization Elements
- **`AppLocalizations` (Abstract Class)**: Exposes the full application string interface, offering factory lookups (`AppLocalizations.of(context)`) and static delegate lists.
- **`_AppLocalizationsDelegate` & `lookupAppLocalizations`**: Resolution mechanisms wiring the requested device `Locale` into the specific language implementation.
- **`AppLocalizationsEn` & `AppLocalizationsEs` (Concrete Classes)**: Autogenerated implementers containing the localized literals and parameter interpolation routines.

---

## 5. Interfaces Section

The component exposes well-defined, static, and immutable interfaces:

- **Theme Interface**: Consumed directly via static properties (`AppStyles.spaceMD`, `AppStyles.errorAccent`) or injected at the root of the app (`MaterialApp(theme: AppStyles.darkTheme)`).
- **Utility Interface**: Invoked explicitly as pure functions (`AppDateFormatter.format(timestamp)`) or as standard Dart extensions (`myDate.floorToHour()`).
- **Localization Interface**: Retrieved from the inherited widget context. Once acquired via `final l10n = AppLocalizations.of(context)!`, components access localized strings through direct property getters (`l10n.dbBtnClearData`) or method calls (`l10n.homeGapHours('2')`).

---

## 6. Dependencies Section

Adhering to Clean Architecture, this core component has **zero outward coupling** to other application modules and avoids heavy third-party packages to maximize performance.

### 6.1 External Dependencies
- **Dart SDK (`dart:core`)**: Utilized for `DateTime`, `String`, numbers, and logic manipulation.
- **Flutter Framework (`package:flutter/material.dart`)**: Provides foundational types (`Color`, `ThemeData`, `TextStyle`, `Locale`, `LocalizationsDelegate`).
- *Note:* It deliberately avoids dependencies like `intl` to reduce application payload and initialization time.

### 6.2 Inbound Dependencies
The component is universally imported by higher-level modules, primarily the Presentation Layer:
- **Screens**: `HomeScreen`, `NearbyScreen`, `ConfigScreen`, `StorageScreen` rely on `AppStyles` for layout/colors, `AppDateFormatter` for timestamps, and `AppLocalizations` for all UI text.
- **Widgets**: Reusable visual blocks like `InferenceCard` utilize specific decorators (`aiRecommendationCard`) and localized warnings.
